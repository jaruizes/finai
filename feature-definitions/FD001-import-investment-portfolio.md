# Import Investment Portfolio

## Purpose

FinAI needs to establish the current state of an investor's investment portfolio as canonical domain information.

This feature allows an investor to provide a portfolio and its current positions so that subsequent FinAI capabilities can reason about what the investor owns.

The imported information represents the investor's stated portfolio. This feature does not enrich, value, analyse, or make recommendations about the portfolio.

## Scope

This feature provides the initial import of an investment portfolio into FinAI.

The import establishes:

- the Portfolio;
- its current Positions;
- the Financial Instrument represented by each Position;
- an optional Investment Thesis associated with each Position.

The import represents the current state of the portfolio. It does not represent the transactions or acquisition lots that produced that state.

FinAI must validate the complete supplied portfolio before establishing it as canonical portfolio information.

An invalid import must not result in a partially established portfolio.

---

## Information Model

### Portfolio

#### Definition

A Portfolio represents a collection of current investment positions owned by an investor.

It provides the context in which Positions exist.

A Portfolio must contain at least one Position.

#### Required information

- **Name** — human-readable name freely chosen by the investor.
- **Positions** — one or more current investment Positions.

#### Optional information

None currently defined.

#### Generated by FinAI

- **Portfolio ID** — stable identifier assigned by FinAI and independent from the investor-provided name.

#### Relationships

- A Portfolio contains one or more Positions.
- A Position belongs to exactly one Portfolio.

#### Does not represent

A Portfolio does not represent:

- an investment account or broker account;
- transaction history;
- orders;
- cash movements;
- portfolio valuation;
- portfolio performance;
- a portfolio valuation currency.

A currency used to value a Portfolio may be introduced by a future portfolio valuation capability. It is not intrinsic to the Portfolio in this feature.

---

### Position

#### Definition

A Position represents the investor's current aggregated holding of one Financial Instrument within a Portfolio.

A Position describes the current holding, not the individual transactions or acquisition lots that produced it.

A Financial Instrument may appear only once within a Portfolio.

#### Required information

- **Financial Instrument** — the instrument being held.
- **Quantity** — current quantity held. It must be greater than zero.
- **Acquisition Currency** — currency associated with the acquisition information, expressed using an ISO 4217 alphabetic currency code.

#### Optional information

- **Average Acquisition Price** — average acquisition price of the current Position when known by the investor.
- **Investment Thesis** — investor-provided rationale for holding the Position.

#### Generated by FinAI

- **Position ID** — stable identifier assigned by FinAI.

#### Relationships

- A Position belongs to exactly one Portfolio.
- A Position represents exactly one Financial Instrument.
- A Position may have one Investment Thesis.

#### Business constraints

- Quantity must be greater than zero.
- A zero quantity is invalid.
- Negative quantities are invalid.
- The same Financial Instrument cannot occur more than once within the same Portfolio.
- Average Acquisition Price may be omitted when the investor does not know it.
- Acquisition Currency must still be specified even when Average Acquisition Price is unknown.

#### Does not represent

A Position does not represent:

- an individual purchase or sale;
- an order;
- a tax lot;
- transaction history;
- current market value;
- unrealised profit or loss.

---

### Financial Instrument

#### Definition

A Financial Instrument represents an identifiable financial asset held through a Position.

The first version of this feature supports:

- Stocks;
- ETFs.

Other types of financial instruments are outside the scope of this feature.

#### Required information

- **Ticker** — trading symbol of the instrument.
- **Exchange** — market in which the ticker is interpreted, identified using an ISO 10383 Market Identifier Code (MIC).
- **Instrument Type** — `STOCK` or `ETF`.

The identity of a Financial Instrument in this version is defined by the combination of:

**Ticker + Exchange MIC**

The Exchange must be identified using an ISO 10383 Market Identifier Code (MIC).

A ticker by itself is not considered sufficient to identify a Financial Instrument.

The first version supports one identification mechanism only.

#### Optional information

- **Display Name** — human-readable name of the instrument.

#### Generated by FinAI

- **Financial Instrument ID** — canonical identifier assigned by FinAI.

#### Relationships

- A Financial Instrument may be referenced by Positions in different Portfolios.
- The same Financial Instrument may appear only once within a single Portfolio.

#### Does not represent

A Financial Instrument in this feature does not establish:

- ISIN or other additional financial identifiers;
- current market price;
- company fundamentals;
- sector or industry classification;
- geographical exposure;
- market events;
- risk information;
- external enrichment data.

Additional identifiers such as ISIN may be introduced by a future instrument resolution or enrichment capability.

---

### Investment Thesis

#### Definition

An Investment Thesis represents the investor's own rationale for holding a Position.

It captures why the investor believes the investment belongs in the portfolio and provides context that future FinAI capabilities may use when analysing the investment.

#### Information

- **Thesis** — optional free-form text supplied by the investor.

No structured thesis model is introduced in this version.

#### Relationships

- A Position may have zero or one Investment Thesis.
- An Investment Thesis belongs to exactly one Position.

#### Does not represent

An Investment Thesis is not:

- financial advice;
- a FinAI-generated recommendation;
- a prediction that the investment will succeed;
- a buy, sell, or hold instruction.

The content represents the investor's own rationale.

---

## Business Rules

1. One import represents exactly one Portfolio.

2. A Portfolio must contain at least one Position.

3. The Portfolio name is freely chosen by the investor.

4. FinAI generates a Portfolio ID independently from the Portfolio name.

5. Every Position belongs to the imported Portfolio.

6. Every Position references exactly one Financial Instrument.

7. A Financial Instrument may appear only once within the Portfolio.

8. Financial Instrument identity in this version is determined by `Ticker + Exchange MIC`.

9. Exchange values must use ISO 10383 Market Identifier Codes (MICs).

10. A Position represents an aggregated current holding rather than individual acquisition transactions or tax lots.

11. Position Quantity must be greater than zero.

12. Average Acquisition Price is optional because the investor may not know it.

13. Acquisition Currency is required and must use an ISO 4217 alphabetic currency code.

14. Only Stocks and ETFs are supported in this version.

15. Investment Thesis is optional free-form investor-provided text.

16. Financial information supplied during import must not be generated, corrected, enriched, or inferred by an LLM.

17. FinAI must validate the complete import before establishing it as canonical portfolio information.

18. Validation must examine the complete import and report all detected validation errors together.

19. An invalid import must not leave a partially imported Portfolio.

20. Importing a portfolio must not trigger market-data retrieval, portfolio valuation, risk analysis, investment analysis, or recommendations.

## Import Outcomes

### Successful Import

When the complete Portfolio is valid, FinAI establishes it as canonical domain information.

The successful outcome must contain:

- a stable machine-readable success code;
- the Portfolio ID generated by FinAI.

### Failed Import

When any part of the supplied Portfolio is invalid:

- the complete import fails;
- no partial Portfolio is established;
- FinAI examines the complete supplied Portfolio;
- all detected validation errors are returned together;
- each error contains a stable machine-readable error code;
- each error contains a human-readable descriptive message explaining the reason.

### Error Identification

Import error codes must follow a stable FinAI portfolio-import namespace.

The expected format is:

`PORT-IMP-NNNN`

For example:

`PORT-IMP-0001`

The exact catalogue and meaning of individual error codes must be defined as part of the formal API contract.

Error codes are part of the machine-readable contract and must not depend on the language used for the descriptive message.

Human-readable error messages may be localized in future versions without changing the corresponding error code.

The internationalization mechanism used to select or render localized messages is outside the scope of this feature.

## Expected Scenarios

### Valid portfolio

An investor supplies a Portfolio with:

- a name;
- at least one valid Position.

Each Position contains:

- a supported Financial Instrument;
- a quantity greater than zero;
- an acquisition currency expressed using ISO 4217;
- optionally an average acquisition price;
- optionally an Investment Thesis.

FinAI validates the complete Portfolio and establishes it as canonical domain information.

The result contains a success code and the generated Portfolio ID.

### Unknown acquisition price

An investor supplies a valid Position but does not know its Average Acquisition Price.

The Position remains valid provided the other required information, including Acquisition Currency, is supplied.

### Invalid quantity

A Position has a quantity equal to zero or lower.

FinAI reports the invalid quantity and rejects the complete import.

### Duplicate financial instrument

Two Positions within the same Portfolio reference the same combination of Ticker and Exchange MIC.

FinAI reports the duplicate and rejects the complete import.

### Unsupported financial instrument

A Position references a Financial Instrument whose type is neither Stock nor ETF.

FinAI reports the unsupported instrument type and rejects the complete import.

### Invalid currency

A Position contains an Acquisition Currency that is not a recognized ISO 4217 alphabetic currency code.

FinAI reports the invalid currency and rejects the complete import.

### Multiple validation errors

Several Positions contain different validation errors.

FinAI validates the complete supplied Portfolio and reports all detected errors together.

No part of the Portfolio is established.

### Portfolio with investment thesis

A Position contains free-form Investment Thesis text supplied by the investor.

FinAI preserves that text and associates it with the Position.

### Portfolio without investment thesis

A Position does not contain an Investment Thesis.

The Position remains valid.

## Out of Scope

The following capabilities are explicitly outside this feature:

- portfolio re-import and reconciliation;
- portfolio history and versioning;
- position history;
- transaction history;
- individual purchase or sale transactions;
- tax lots;
- cash movements;
- orders;
- short positions;
- portfolio valuation;
- portfolio valuation currency;
- profit and loss calculation;
- portfolio weighting;
- performance calculation;
- currency conversion;
- market prices;
- market-data retrieval;
- instrument enrichment;
- additional financial identifiers such as ISIN;
- company fundamentals;
- sector, industry, and geographical enrichment;
- position-role classification;
- market news;
- market events;
- risk calculation;
- portfolio analysis;
- investment-thesis evaluation;
- AI-generated investment theses;
- investment recommendations;
- trade execution;
- error-message internationalization mechanism.

These capabilities may be introduced through separate feature specifications.

## Resolved Design Decisions

The following domain decisions are explicit for this feature:

- Exchange values use ISO 10383 Market Identifier Codes (MICs).
- Financial Instrument identity is `Ticker + Exchange MIC`.
- Success responses are not required to use a namespaced success-code convention analogous to `PORT-IMP-NNNN`.
- Failed imports use stable machine-readable error codes following the `PORT-IMP-NNNN` format, together with human-readable descriptive messages.
